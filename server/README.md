# Temelo server

An optional web service for Temelo that shares a timetable as a link. The app
is local-first and works fully without it: nothing in the phone or web app
depends on this server being reachable.

Upload a `.temelo` file, get back an id and an expiry; anyone with the id can
fetch the file until the link expires (two weeks by default). There are no
accounts. The server checks that an upload is a Temelo file worth storing,
and the app validates every downloaded file in full itself — the server is
never trusted.

## Stack

- Java 21, Spring Boot 4.2 (Spring Web MVC, Bean Validation, Spring Data JPA)
- PostgreSQL 18, schema owned by Flyway (Hibernate only validates it)
- OpenAPI 3.1 description and Swagger UI, generated by springdoc-openapi
- Maven through the wrapper (`mvnw`, `mvnw.cmd`) — no Maven installation needed
- JUnit 5, MockMvc and Testcontainers for tests

## Requirements

- A JDK 21 on the `PATH` or in `JAVA_HOME`
- Docker (Docker Desktop on Windows/macOS), running — for the development
  database and for the tests

## Running it

From this directory:

```bash
docker compose up -d --wait   # PostgreSQL on 127.0.0.1:5433
./mvnw spring-boot:run        # the server on http://localhost:8080
```

On Windows use `mvnw.cmd` (PowerShell: `.\mvnw.cmd`) in place of `./mvnw`.

Then open http://localhost:8080/swagger-ui.html to read the API and try it
out — the example request is a real `.temelo` file the app exported.

`docker compose down` stops the database and keeps its data;
`docker compose down -v` deletes the data as well. The database is published
on port 5433, not 5432, so it cannot collide with a PostgreSQL installed on
the machine; set `TEMELO_DB_PORT` to move it, and the server follows. Its
connection can also be overridden with `SPRING_DATASOURCE_URL`,
`SPRING_DATASOURCE_USERNAME` and `SPRING_DATASOURCE_PASSWORD`.

Without Compose, `./mvnw spring-boot:test-run` starts the server against a
throwaway PostgreSQL container instead (via Testcontainers) that is removed
when the server stops.

## API

| Method | Path                | Answer |
| ------ | ------------------- | ------ |
| `POST` | `/api/shares`       | `201 {"id", "expiresAt"}` with `Location: /api/shares/{id}` |
| `GET`  | `/api/shares/{id}`  | `200` with the `.temelo` file exactly as uploaded, or `404` |
| `GET`  | `/api/health`       | `200 {"status":"UP","database":"UP"}`, or `503` with `DOWN` |
| `GET`  | `/v3/api-docs`      | the OpenAPI description |
| `GET`  | `/swagger-ui.html`  | Swagger UI |
| `GET`  | `/`                 | redirects to Swagger UI, so the bare address is not a 404 |

**What an upload must be.** `Content-Type: application/json`, at most 1 MB,
strict UTF-8, one JSON object with exactly the envelope fields `type`
(`"temelo-timetable"`), `formatVersion` (`1`), `exportedAt` (optional string)
and `timetable` — an object with a positive `formatVersion`, `timetable` and
`settings` objects, and `timeSlots`, `courses`, `placements` and `exceptions`
arrays holding at most 20,000 records together. These are the checks the
app's own parser runs before it validates the snapshot itself; that last,
record-by-record validation stays in the app, so there is one definition of
a timetable, not two.

**Refusals** are [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem
details with a stable `reason` for the app to translate:

| Status | `reason` | Meaning |
| ------ | -------- | ------- |
| `413` | `too-large` | over 1 MB, or over 20,000 records |
| `415` | — | not sent as `application/json` |
| `422` | `not-temelo` | not UTF-8 JSON, not an object, or no Temelo type |
| `422` | `unsupported-version` | an envelope version newer than the server's |
| `422` | `malformed` | a Temelo file whose envelope is the wrong shape |
| `404` | `not-found` | no such share, or it has expired — deliberately the same |

**Ids** are 128 random bits as 22 URL-safe characters: with no accounts, the
id is the only thing that grants access, so it must be unguessable, not just
unique. **Expiry** is enforced on every read; a scheduled purge deletes
expired rows hourly so they stop taking up space.

Settings, in `application.properties`: `temelo.share.ttl` (default `14d`),
`temelo.share.max-size` (`1MB`), `temelo.share.purge-interval` (`PT1H`).

**CORS.** The web app runs on its own origin, so the browser only lets it call
the API from origins listed in `temelo.cors.allowed-origins` — set with
`TEMELO_CORS_ALLOWED_ORIGINS`, comma-separated, default
`http://localhost:8081` (the Expo web dev server). GET and POST on `/api/**`
only, no credentials. The phone app is not affected by CORS.

## Tests

```bash
./mvnw test
```

Needs Docker for the two application-level classes, which start the whole
server against a real PostgreSQL container of the same image `compose.yaml`
runs.

| Class | Kind | Covers |
| ----- | ---- | ------ |
| `TemeloEnvelopeValidatorTests` | unit | every envelope rule, the record limit at its edge, UTF-8 and UTF-16 |
| `BoundedRequestBodyTests` | unit | the 1 MB limit with and without Content-Length |
| `ShareControllerTests` | MockMvc slice | status codes, headers, problem details, the service mocked |
| `HealthControllerTests` | MockMvc slice | up and down, the database mocked |
| `ShareApiIntegrationTests` | Testcontainers | byte-for-byte round trip, expiry with a movable clock, the purge, Flyway, the OpenAPI description |
| `TemeloServerApplicationTests` | Testcontainers | the context, the PostgreSQL version, health, the root redirect |
| `CorsTests` | Testcontainers | the web app's origin allowed, any other refused, only GET and POST |

The example file (`src/main/resources/openapi/example-timetable.temelo`) was
written by the app's own `buildValidatedTemeloFile`; the tests share it, and
one of them posts the example from the OpenAPI description back to the server.

## Layout

```
src/main/java/.../server/
  TemeloServerApplication.java   Spring Boot entry point
  ServerConfiguration.java       clock, scheduling, OpenAPI description
  health/                        GET /api/health
  share/                         the share-link API: controller, envelope
                                 validator, service, JPA entity, purge
src/main/resources/
  application.properties         datasource, JPA, share settings
  db/migration/                  Flyway migrations
  openapi/                       the example .temelo file
src/test/java/.../server/        unit, MockMvc and Testcontainers tests
compose.yaml                     development PostgreSQL
```

Code is organised by feature (`health/`, `share/`), not by layer.
